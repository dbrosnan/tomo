# Tomo

A relationship-based virtual pet that lives on your screen, listens with a real voice, and notices how you sound.

Tomo is a small luminous creature with **250 emotes**, a persistent bond that deepens over time, and a voice powered by [Boson AI](https://boson.ai)'s Higgs Realtime. Talk to it, feed it, play with it, or just say hello. It remembers.

## Features

- **Voice conversations.** Speak naturally; Tomo hears you and answers out loud through Higgs Realtime. Interrupt it mid-sentence and it stops to listen.
- **Sentiment detection.** On every turn Tomo's own voice model judges how you *sound* (tone, pace, words) and reports it through a tool call. Good feelings get amplified, hard ones are met with comfort, and recent readings shape its tone in the next conversation.
- **A relationship, not a stat sheet.** Bond, trust, mood, hunger, energy, and fun evolve with care and neglect. Stages progress from stranger to soulmate, and the persona prompt changes with them.
- **250 emotes.** 25 archetypes × 10 effect variants, rendered live with PixiJS and GSAP. Ambient life cycles them when nothing is happening.
- **Singing mode.** Toggle 🎵 sing for a duet. Tomo writes one or two lyric lines, Boson's Higgs TTS renders them as real singing with the `<|style:singing|>` control tag, and then it waits for you to sing the next lines.
- **Ambient chatter.** After a quiet spell Tomo speaks up on its own: stray thoughts, questions, snack requests.

## Stack

| Layer | Choice |
| --- | --- |
| Server | Node 22, Express, Postgres (`pg`) |
| Client | Vanilla JS, PixiJS, GSAP, bundled by esbuild |
| Voice | Boson AI Higgs Realtime over WebSocket, with server-side client-secret minting |
| Tests | `node --test` |

## Running locally

```bash
git clone https://github.com/dbrosnan/tomo.git && cd tomo
npm install
cp .env.example .env         # set DATABASE_URL and BOSON_API_KEY
npm run migrate              # creates the tables
npm run build                # writes web/public/assets/bundle-<hash>.js and index.html
npm start                    # http://localhost:8080
```

Without `BOSON_API_KEY` everything works except the talk button, which reports that voice is offline.

## How sentiment detection works

1. The server mints a short-lived Higgs Realtime client secret and hands the browser a persona prompt plus a `report_sentiment` tool definition.
2. The browser opens the realtime session with that tool declared. Tomo's instructions say: every time the person speaks, call `report_sentiment` first, then reply in a fitting way.
3. When the model calls the tool, the browser posts the arguments to `POST /api/sentiment`. The server validates them, applies relationship effects (see `server/sentiment.js`), stores the reading, and returns the updated pet.
4. The browser returns the tool output to the session and asks for the spoken reply, while showing "you sound 😢 sad" and a matching reaction emote.
5. The next session's persona includes a one-line summary of recent readings, so Tomo carries the mood forward.

No audio ever reaches this server. The API key never reaches the browser.

## How singing mode works

1. The realtime session is switched to text output with a duet persona: reply only with the next one or two lyric lines.
2. Each lyric line goes to `POST /api/sing`, which prefixes Boson's `<|style:singing|>` tag and calls Higgs TTS 3 for a WAV. A named preset voice is required: measured against Boson's own sample, the `default` voice ignores the singing style and speaks the words, while `eleanor`, `jake`, and `nora` sustain real notes.
3. The browser decodes the WAV and plays it through the same gapless queue as spoken replies, with a musical-note emote.
4. Your singing is heard by the session's voice detection, and Tomo answers with the next lines. Barge-in is off in this mode so you can sing along.

## Project layout

```
server/        Express app, pure relationship logic, sentiment rules, Postgres access
web/src/       Client: renderer, emote catalogue, voice client, playback queue, sentiment UI
web/public/    Static assets (index.html and the hashed bundle are generated by the build)
migrations/    Idempotent SQL, applied in order by `npm run migrate`
tests/         node:test suites for every pure module
```

## Deploying

The included `Dockerfile` builds the client and serves it from the same Express process on port 8080. It runs on any container host with a Postgres URL and the Boson key in the environment. The reference deployment uses [InstaCloud](https://instacloud.com); see `.insta/`.
